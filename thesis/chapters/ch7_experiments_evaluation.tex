\chapter{Experiments and System Evaluation}
\label{chap:experiments}

This chapter evaluates the thesis claims as bounded empirical questions rather than as a single benchmark exercise. The experiments serve different roles: some establish a labeled reference point, some test how monitoring signals behave under degraded conditions, some probe sensitivity to production-style preprocessing choices, and some evaluate whether governance decisions improve operational behavior. This distinction matters because a strong offline metric alone does not answer RQ1--RQ4, especially in wearable settings where transfer across activities, users, or collection conditions is known to be fragile \cite{dhekane2024transfer,sahu2025anxiety}.

A second design choice is that claims are intentionally limited to what the stored artifacts can support. The chapter therefore distinguishes between evidence that supports a thesis claim, evidence that only suggests a trend, and negative results that show why certain interventions should not be interpreted as quality improvements. Reproducibility follows the artifact structure described in Chapter~\ref{chap:implementation}: the results below are backed by versioned run outputs, evaluation JSON files, and thesis summary tables rather than by ad hoc inspection alone \cite{amershi2019mlops,kreuzberger2023mlops}.

\section{Evaluation Philosophy and Evidence Map}

An MLOps-oriented thesis needs multiple experiment types because different risks appear at different lifecycle stages. Labeled reference evaluation is needed to show that the retained model is competent on known data. Production-style ablations are needed to expose train--serve sensitivity. \section{Baseline Reference on Labeled Data}

\textbf{Purpose.} This experiment establishes the labeled reference point for the retained deployment model. The question is not whether the thesis achieves a novel benchmark, but whether later production-style failure modes should be interpreted relative to a competent baseline.

\textbf{Data and setup.} The model used here is the pre-sprint retrained 1D-CNN + BiLSTM artifact \texttt{har\_model\_20260327\_223917.keras}, which served as the original labeled baseline before the May 2026 model sprint. This model is \emph{not} Model~A (the defended proof-of-concept runtime candidate selected in the May sprint). It is used here specifically to establish a labeled-set reference baseline and to provide context for later production-style sensitivity experiments. Model~A's actual defended numbers --- 42.4\% accuracy on the all\_users diagnostic and 37.6\% on User~7 --- are reported in the ABC comparison (Section~\ref{sec:abc_comparison}). The pre-sprint model's stored training report recorded 92.2\% final accuracy and 92.2\% macro F1 under the configured offline training procedure; the thesis-facing reference evaluation ran the same model end-to-end through the pipeline evaluation stage on a labeled set containing 3{,}852 windows across all eleven classes.

\textbf{Method.} The pipeline was executed without changing the retained model or evaluation logic. Predictions were generated for the labeled reference set, and the resulting JSON artifact was used to compute standard classification metrics together with confidence and temporal summary statistics.

\textbf{Metrics.} Accuracy and macro F1 quantify recognition quality on the labeled reference set. Mean confidence and uncertain-rate quantify how decisive the model is under matched conditions. Dominant-class share and transition rate provide a simple check against pathological collapse or temporal instability.

\textbf{Results.} The labeled end-to-end reference evaluation reached 98.9\% accuracy and 98.9\% macro F1. Mean confidence was 98.6\%, the uncertain rate was 0.18\%, the dominant predicted class occupied only 10.0\% of windows, and the transition rate was 0.032 (Table~\ref{tab:labeled_baseline_reference}).

\textbf{Interpretation.} This reference point shows that the retained model is strong when train and serve conditions remain aligned. \textbf{Limitation.} This evaluation is window-level and distribution-matched. It supports internal competence on a labeled reference set, but it does not establish subject-independent deployment performance, clinical validity, or robustness across unseen collection conditions.

\section{Uncertainty Under Dataset Realism Change}

\textbf{Purpose.} This experiment asks whether the monitoring-oriented signals used in the pipeline move in a meaningful direction when input realism degrades. The question is operational: can confidence and uncertainty summaries provide useful evidence when labels are absent or only partially available?

\textbf{Data and setup.} The same retained model and the same evaluation path were applied to three datasets: an actual labeled reference set, Synth Codex, and Synth Other. Each dataset contains 3{,}852 windows, which keeps the comparison controlled at the evaluation level.

\textbf{Method.} No model retraining or threshold retuning was performed between runs. For each dataset, the pipeline produced a classification report together with confidence, uncertainty, and temporal summaries. The comparison therefore isolates dataset realism as the main manipulated factor.

\textbf{Metrics.} Accuracy and macro F1 remain useful where labels exist, but the central monitoring metrics here are mean confidence, uncertain rate, and transition rate. These matter because they remain observable even when production labels are unavailable. A full calibration study would additionally require dedicated metrics such as ECE; that is not the aim of this comparison.

\textbf{Results.} The actual labeled set produced 98.9\% accuracy, 98.9\% macro F1, 98.6\% mean confidence, 0.18\% uncertain windows, and a transition rate of 0.032. Under the same evaluation path, Synth Codex dropped to 70.4\% accuracy and 71.1\% macro F1, with 86.8\% mean confidence, 6.5\% uncertain windows, and a transition rate of 0.285. Synth Other showed substantially stronger degradation, with 34.6\% accuracy and 31.7\% macro F1, while mean confidence decreased to 77.7\% and uncertain windows increased to 14.5\%, with a transition rate of 0.282. Figure~\ref{fig:actual_vs_synthetic} and Table~\ref{tab:actual_vs_synth} summarize the comparison.

\textbf{Interpretation.} The comparison supports the narrower claim that confidence-based and uncertainty-based monitoring signals respond directionally to realism degradation. Relative to the actual labeled reference, the two synthetic datasets show degradation at different severity levels, and the monitoring signals scale with that difference. Synth Codex shows a drop of approximately 12 percentage points in mean confidence (98.6\% to 86.8\%) and a rise in uncertain windows from 0.18\% to 6.5\%. Synth Other shows substantially stronger degradation: accuracy falls to 34.6\% compared to Synth Codex's 70.4\%, mean confidence drops a further 9 percentage points to 77.7\%, and uncertain windows rise to 14.5\%. This gradient matters for RQ1 because it indicates that the monitoring layer can surface problematic behavior even when production labels are unavailable, and that the signals scale with the severity of the distributional mismatch rather than triggering uniformly. It should not be interpreted as proof that synthetic data is uniformly poor; rather, it shows that the monitoring layer is sensitive to the degree of realism degradation \cite{gal2016dropout,guo2017calibration}.

\textbf{Limitation.} This is not a full calibration study, and it does not establish universal out-of-distribution detection. The comparison only shows directional movement of confidence, uncertainty, and temporal instability under the tested synthetic conditions.

\section{Preprocessing Sensitivity Under Replay}

\textbf{Purpose.} This experiment asks how strongly production-style inference behavior depends on preprocessing consistency. The targeted question for RQ2 is whether seemingly reasonable preprocessing changes improve behavior automatically, or whether they can instead worsen collapse.

\textbf{Data and setup.} The ablation was run on 25 production-style session pairs under four preprocessing configurations: A = baseline, B = calibration only, C = gravity removal only, and D = gravity removal plus calibration. The same retained model and the same downstream evaluation path were used for every run, yielding 100 total evaluations.

\textbf{Method.} Only the preprocessing configuration was changed. Each session pair was replayed under configurations A--D, and the resulting prediction distributions were aggregated across sessions. This isolates the effect of gravity removal and calibration choices from model choice and from downstream monitoring logic.

\textbf{Metrics.} Mean unique classes predicted measures behavioral diversity and acts as a coarse proxy against single-class collapse. Mean hand-tapping share measures how strongly the output distribution is dominated by the class that was historically problematic in production-style runs.

\textbf{Results.} The four configurations separate clearly. On mean unique classes, the configurations score A = 7.08, B = 7.88, C = 5.32, and D = 9.72. On mean hand-tapping share, they score A = 78.37\%, B = 73.22\%, C = 96.72\%, and D = 50.14\%. Configuration D therefore achieves the broadest class diversity, while Configuration C is the clearest warning case: gravity removal alone worsened collapse instead of improving it (Figure~\ref{fig:ablation_config_comparison}, Table~\ref{tab:ablation_summary}).

\textbf{Limitation.} The evidence is based on unlabeled production-style sessions and distributional output summaries rather than on ground-truth activity labels. It therefore supports sensitivity of pipeline behavior, not a universal claim that gravity removal is generally harmful in wearable HAR.

\section{Governance and Model-Mutation Evidence}

Once the baseline and monitoring context are established, the remaining experiments evaluate governance choices more directly: how alerts should be aggregated, how much collapse can be attributed to model choice, and whether a plausible intervention bundle improved model quality or merely changed routing behavior.

\subsection{Trigger-Policy Evaluation}

\textbf{Purpose.} This experiment asks which retraining-trigger policy provides the most defensible governance trade-off. The question is central to RQ3 because the thesis claims that controlled retraining should be gated by explicit policy rather than by the first alert signal that fires.

\textbf{Data and setup.} The policy comparison uses a stored replay evaluation over 16 episodes. The evaluated variants are \texttt{single\_signal}, \texttt{two\_of\_three}, and three cooldown variants layered on top of the two-of-three voting rule.

\textbf{Method.} The monitored evidence stream was held fixed while the trigger aggregation policy was varied. The artifact reports precision, episode recall, trade-off F1, and false alarm rate for each rule, which makes the comparison about governance logic rather than about classifier retraining.

\textbf{Metrics.} Precision measures how often alerts correspond to true episodes. Episode recall measures how many of the 16 episodes are still detected. Trade-off F1 summarizes the balance between responsiveness and reliability, while false alarm rate captures the operational cost of noisy triggering.

\textbf{Results.} The \texttt{two\_of\_three} policy provides the strongest overall balance among the tested rules. It records precision 0.9878, episode recall 1.0, trade-off F1 0.9939, and false alarm rate 0.0069. By contrast, \texttt{single\_signal} is materially noisier, with precision 0.8406, trade-off F1 0.9134, and false alarm rate 0.1389. Cooldown variants reduce trigger volume further, but the 24-hour cooldown also misses two of the 16 episodes and drops recall to 0.875 (Table~\ref{tab:trigger_policy}, Figure~\ref{fig:trigger_policy_comparison}).

\textbf{Interpretation.} This experiment supports the thesis claim that governance quality depends on how multiple monitoring signals are aggregated, not only on whether those signals exist. In the tested replay, a two-of-three voting rule preserves full episode recall while sharply reducing false alarms relative to single-signal triggering. That makes retraining governance materially safer because fewer unnecessary mutations are proposed while the relevant episodes are still detected \cite{hewage2022mlops,khattak2023mlhops}.

\textbf{Limitation.} The policy comparison is bounded to one replay dataset and one family of thresholds. It identifies the best rule among the tested variants, but it does not establish a universally optimal trigger policy for all wearable HAR deployments.

\subsection{Calibrated MMD Drift-Audit and Staged Governance Test}
\label{sec:mmd_branch_evaluation}

\textbf{Purpose.} This experiment asks whether a stronger distribution-level drift signal improves governance quality, not merely drift visibility. The methodological distinction is important: the defended runtime keeps a raw physical production input contract, while MMD is evaluated as a batch-level drift-audit signal. The question is therefore not ``scaler versus MMD'', but whether calibrated MMD should replace or augment the defended runtime drift monitor in the governance path.

\textbf{Data and setup.} The comparison reuses the same retained model and the same four replay datasets used in the branch-comparison artifacts: one healthy labeled reference set, two degraded labeled synthetic/replay sets, and one degraded unlabeled synthetic/replay set. No new data were invented for this experiment.

\textbf{Method.} The experiment was run in three rounds. First, the current lightweight z-score mean-shift drift monitor was compared with an MMD branch while all other conditions were held fixed. Second, MMD thresholds were calibrated from healthy reference comparisons by repeatedly splitting the reference-window artifact and computing reference-vs-reference MMD over per-window summary features. Third, a staged MMD policy was evaluated with healthy, warning, and critical MMD bands. The staged policies allowed MMD to create warning-level alerts, but did not allow MMD alone to queue retraining.

\textbf{Metrics.} Drift-warning count measures visibility of distribution shift. Risk alerts measure non-mutating governance surfacing. Queue/retrain count and recall measure whether the policy actually improves final mutation decisions. Precision, recall, and false alarm rate are reported where the replay labels define healthy versus problematic datasets.

\textbf{Results.} The calibration used 500 reference-vs-reference comparisons with 384 windows per side. The empirical warning threshold was 0.00276403 (95th percentile), and the critical candidate threshold was 0.00322704 (99th percentile). These thresholds are dataset-specific and should not be interpreted as universal MMD values.

The branch comparison showed that MMD was more sensitive than the current drift monitor on degraded replay sets. The current policy produced 0 drift warnings out of 4 datasets, 0 risk alerts, and 0 queue/retrain decisions. With MMD active in trigger evaluation, drift warnings increased to 3 of 4 datasets and risk alerts increased to 3, with risk precision 1.0 and risk recall 1.0. Queue/retrain decisions remained 0.

The final staged-policy redesign confirmed the same governance boundary (Table~\ref{tab:mmd_staged_policy}). The current baseline had risk recall 0.0 and queue recall 0.0. The conservative MMD staged policy marked the three degraded datasets as MMD-critical but produced risk recall 0.0 and queue recall 0.0 because no behavior-risk signal agreed with MMD under the configured thresholds. The hybrid staged policy produced 3 risk alerts, risk recall 1.0, and false alarm rate 0.0, but queue recall still remained 0.0 because retraining was not permitted on MMD alone.

\textbf{Interpretation.} The result supports a mature distinction between monitoring strength and governance quality. \textbf{Limitation.} The comparison is bounded to four replay datasets, one retained model, one reference artifact, and one per-window summary-feature representation. It does not establish universal MMD thresholds, subject-independent robustness, or production-readiness of MMD as a runtime retraining trigger.

\subsection{Same-Input Old Versus New Model Comparison}

\textbf{Purpose.} This experiment tests RQ4 directly by asking whether the severe collapse observed on a problematic production-style session is primarily attributable to the input data itself or to the active model.

\textbf{Data and setup.} The comparison uses one unlabeled raw accelerometer/gyroscope pair containing 3{,}162 windows. Three runs are compared: the historical old-model reference, the new retained retrained model, and a controlled rerun of the old model on the same input pair.

\textbf{Method.} The input session was held constant while the active model was varied. The old-model rerun acts as a control to verify that any previously observed collapse pattern was reproducible and not an artifact of a single historical log.

\textbf{Metrics.} Mean confidence and uncertain rate quantify decisiveness. Top-class share measures collapse severity. The number of predicted classes measures how broadly the model uses the class space on the fixed input session.

\textbf{Results.} The old-model reference produced mean confidence 0.876, uncertain rate 4.4\%, top-class share 85.6\%, and predictions spanning only 9 of the 11 classes. The new retrained model produced mean confidence 0.7897, uncertain rate 15.0\%, top-class share 29.0\%, and predictions spanning all 11 classes. The controlled old-model rerun reproduced the original collapse pattern almost exactly, with 0.8762 mean confidence, 4.40\% uncertain windows, 85.64\% top-class share, and 9 predicted classes (Table~\ref{tab:old_vs_new_model}, Figure~\ref{fig:old_vs_new_model_comparison}).

\subsection{Systematic 25-Session Comparison: Pseudo-Labeled Versus Raw Retrained Model}
\label{sec:pseudolabel_vs_raw}

\textbf{Purpose.} The single-session comparison in the previous subsection isolated model choice as a driver of collapse on one fixed input. This subsection asks whether that finding holds systematically across all 25 collected production sessions, and whether the observed difference in collapse severity can be explained by the training strategy used for each model.

\textbf{Background: pseudo-label fine-tuning and its bias risk.} The historical model was produced by fine-tuning the mentor-provided 1D-CNN-BiLSTM baseline on unlabeled production sessions using a pseudo-labeling strategy: the model's own high-confidence predictions on unlabeled data were treated as ground-truth labels for a subsequent fine-tuning pass. Pseudo-labeling is a well-studied semi-supervised technique that can improve generalisation when the base model is well-calibrated and the unlabeled data is representative \cite{lee2013pseudolabel}. However, it carries a known failure mode: if the base model already exhibits a prediction bias on the target domain, pseudo-labeling reinforces that bias rather than correcting it, because the generated labels are drawn from the model's own distribution rather than from true ground truth \cite{arazo2020pseudolabel}. In the present case, the production sessions were dominated by wrist-worn hand-tapping motion, and the base model already predicted hand-tapping with high confidence on such inputs. The pseudo-label fine-tuning pass therefore exposed the model predominantly to hand-tapping-labelled windows, amplifying the existing bias into a structural collapse pattern.

\textbf{Data and setup.} All 25 production sessions from the raw-backup collection were processed through stages 1--3 of the standard pipeline to obtain windowed representations. Both models were then run on the same windowed input for each session without any re-preprocessing or threshold change, yielding 50 paired inference runs.

\textbf{Metrics.} The same collapse metrics used in the single-session comparison are applied here: mean confidence, dominant-class share, and number of unique predicted classes. Dominant-class share and class count provide a distributional view across sessions without requiring ground-truth labels.

\textbf{Results.} The aggregate comparison is summarised in Table~\ref{tab:pseudolabel_vs_raw_summary} and Figure~\ref{fig:model_compare_dashboard}. The pseudo-labeled fine-tuned model predicted hand-tapping as the dominant class in 24 of 25 sessions, with a mean dominant-class share of 82.4\% and a mean of 7.1 unique predicted classes. The raw retrained model predicted all 11 classes in 22 of 25 sessions, with a mean dominant-class share of 37.2\% and a mean of 10.5 unique predicted classes. Mean confidence was higher for the fine-tuned model (0.866) than for the raw retrained model (0.791), reflecting the overconfidence that arises when pseudo-label fine-tuning narrows the effective prediction distribution.

One exception is notable in each direction. In session \texttt{2025-07-19}, the fine-tuned model predicted ear-rubbing rather than hand-tapping as dominant (84.6\%), suggesting that this session contained unusual wrist-motion patterns that even the biased model could not assign to hand-tapping. On the raw retrained side, session \texttt{2025-08-11} showed a smoking-dominant collapse at 97.9\% with only 4 predicted classes, indicating that even a well-generalising raw model can collapse on specific session characteristics. Both of these outliers reinforce the thesis case for runtime monitoring rather than assumption-based trust in any fixed model.

\textbf{Interpretation.} This result extends the single-session finding to a systematic cross-session pattern. The pseudo-label fine-tuning process reinforced the hand-tapping dominance already present in the base model's production-facing predictions, producing a model that is more confident on average but far less diverse in its class use. The raw retrained model, trained exclusively on labeled data that covers all 11 activity classes, maintains full class diversity across almost all sessions. This provides direct empirical evidence for the thesis claim that model governance must include both the training strategy and the deployment history as auditable components of the lifecycle, not only model accuracy metrics \cite{amershi2019mlops,kreuzberger2023mlops}. It also directly motivates the collapse guard in Stage~7: a model that collapses with high confidence is not detectable through confidence thresholds alone, which is why dominant-class share was introduced as a complementary monitoring signal.

\textbf{Limitation.} All sessions are unlabeled, so neither model can be ranked by true accuracy on this data. The comparison measures behavioral diversity, not correctness. A model predicting 11 classes per session is not necessarily more accurate than one predicting fewer; it is, however, operationally more defensible as a monitoring subject, because its outputs are not structurally predetermined.

\subsection{Negative Result: Unit-Fix Plus Abstain Intervention}

\textbf{Purpose.} This experiment tests whether an apparently sensible intervention bundle genuinely improved model behavior. The bundle combined g-unit detection and conversion, stream-reuse guarding, and low-motion/out-of-distribution abstain-to-review behavior.

\textbf{Data and setup.} A before/after comparison was run on 26 production sessions. Twenty-five sessions succeeded in both variants; one failed in both due to a corrupted accelerometer file, so the paired aggregate comparison is based on 25 successful sessions.

\textbf{Method.} The baseline pipeline and the modified pipeline were run on the same session set. The modified variant enabled the full intervention bundle, and the resulting thesis summary table was used to compare confidence, dominance, review routing, and run success.

\textbf{Metrics.} Mean confidence is the key quality proxy. Mean dominant-class share measures collapse severity, review share measures abstain routing, and successful-run counts verify that the intervention did not degrade execution reliability.

\textbf{Results.} Mean confidence was unchanged at 0.8578 before and after the intervention. Mean dominant-class share decreased from 81.17\% to 67.34\%, but mean review share after the intervention reached 66.09\%. Both variants succeeded on 25 of 26 sessions, and the number of sessions with dominant-class share at or above 95\% remained three in both variants. Figures~\ref{fig:neg_result_dominant} and \ref{fig:neg_result_review} illustrate the change in routing behavior, and Table~\ref{tab:negative_result_summary} summarizes the paired comparison.

\section{External Evaluation and ABC Model Comparison}
\label{sec:abc_comparison}

\textbf{Purpose.} The earlier sections evaluated model and pipeline behaviour under controlled, replayed, or distribution-matched conditions. This section reports the defended runtime candidate's behaviour on a true cross-user external dataset (User~7) and on a real unlabeled production-style session (Garmin), and compares it against two contrast models. The targeted question is whether the defended pipeline reports an honest external accuracy ceiling and whether the contrast models actually carry the production properties their internal scores would suggest.

\textbf{Data and setup.} Three datasets are used. The User~7 labeled external dataset (99{,}017 rows, 989 windows, 50~Hz, accelerometer unit \(\mathrm{m/s^2}\)) is the primary external evaluation set. The Garmin unlabeled production-style session (130{,}500 rows, 1{,}304 windows, milliG converted to \(\mathrm{m/s^2}\)) is the primary unlabeled runtime test. The all\_users dataset (385{,}326 rows, 3{,}852 windows) is reported as an internal diagnostic only, because it is drawn from the same labeled population used to train Model A.

Three models are compared. Model~A is the defended clean proof-of-concept runtime candidate, run under the clean pipeline contract with a time-major row-wise tensor layout and a persisted Garmin-train-only scaler whose JSON and joblib forms agree to 0.0 absolute difference. Model~B is a legacy/native diagnostic reference that uses a channel-major reshape and fits a StandardScaler on the entire evaluation dataframe at run time; it is reported only as a forensic reference and is not production-safe. Model~C uses the same checkpoint as Model~B but is run under the clean row-wise layout with no scaler, which deliberately exposes checkpoint-contract mismatch behaviour.

\textbf{Method.} Each (model, dataset) pair was run under its declared contract without altering model weights or trigger thresholds, producing the nine evaluations summarised in \texttt{reports/abc\_comparison/abc\_results.csv}. No clean-pipeline run is reported for Model~B because Model~B has no persisted legacy scaler and its tensor layout is incompatible with the clean contract.

\textbf{Metrics.} Accuracy and macro F1 are reported on the labeled datasets. Classes used, mean confidence, uncertain-window percentage, trigger decision, and the auto-retrain flag are reported for all datasets, because they remain observable when labels are absent.

\textbf{Results.} The summary across the External User~7 set and the internal all\_users diagnostic is given in Table~\ref{tab:abc_summary}. On User~7, Model~A reaches 37.6\% accuracy and 34.1\% macro F1 with all 11 classes used and a mean confidence of 0.359; Model~B reaches 43.8\% accuracy and 41.9\% macro F1 with mean confidence 0.775; Model~C reaches 7.6\% accuracy and 2.5\% macro F1 using only 4 of 11 classes with mean confidence 0.748. On the internal all\_users diagnostic, Model~A reaches 42.4\% accuracy and 39.5\% macro F1, Model~B reaches 90.8\% accuracy and 90.9\% macro F1, and Model~C reaches 10.6\% accuracy and 3.6\% macro F1. The Garmin unlabeled run produced 1{,}304 windows for Model~A with mean confidence 0.393, drift status \texttt{HEALTHY}, trigger \texttt{REVIEW}, and \texttt{auto\_retrain=false}.

\textbf{Interpretation.} The interpretation is structured around the six claims this section is intended to support.

\emph{Cross-user generalisation gap on User~7.} Model~A's drop to 37.6\% accuracy on a single external participant is the honest external accuracy ceiling under the defended contract. The retained model is not subject-independent; the User~7 score should be read as evidence of weak cross-user generalisation and domain shift, not as a pipeline failure.

\emph{All\_users diagnostic is not primary evidence.} Model~A's 42.4\% on all\_users is reported for completeness, but the all\_users dataset is drawn from the same labeled training population. It is therefore an internal diagnostic, and the User~7 set remains the primary external-evaluation point.

\emph{Mixed-label window noise is not the main cause.} Of the 989 User~7 windows, only 20 ($2.02\%$) carry mixed activity labels under the majority-label-with-lexicographic-tiebreak windowing policy (3.35\% on all\_users). This rules out window-boundary label noise as the primary explanation for the User~7 accuracy; the dominant explanatory factor is cross-user domain shift.

\emph{Model~B does not transfer cleanly.} The roughly 47-percentage-point gap between Model~B's all\_users score (90.8\%) and its User~7 score (43.8\%) is consistent with its non-persisted full-evaluation scaler and legacy native setup limiting transferability outside the native diagnostic context. The internal score is not a deployment claim. Model~B is therefore retained as a forensic reference and not as a production candidate.

\emph{Model~C proves checkpoint-contract mismatch risk.} Loading the same checkpoint as Model~B but under the clean row-wise layout with no scaler collapses accuracy to 7.6\% on User~7 and 10.6\% on all\_users, with predictions concentrated in 4 and 7 classes respectively. A checkpoint alone is not sufficient: the preprocessing contract under which the checkpoint was trained is what determines runnable behaviour. This is the clearest evidence in the chapter that the model artifact and the preprocessing contract are inseparable governance objects.

\emph{Garmin unlabeled run as runtime-style proof of concept.} The Garmin run produced 1{,}304 windows, a mean confidence of 0.393, drift status \texttt{HEALTHY}, trigger \texttt{REVIEW}, and \texttt{auto\_retrain=false}. This shows that the monitoring and trigger layer can route a real unlabeled session into human review on the basis of confidence and uncertainty signals alone, without ground-truth labels. It is a runtime-style proof of concept, not a production deployment claim.

\textbf{ABC summary.} Model~A is the most reproducible and honest runtime candidate; it has documented low accuracy and calibration limitations on the single external participant, and is presented as such. Model~B is a diagnostic reference whose strong internal score reflects a non-persisted full-evaluation scaler and a legacy native setup that limit transferability. Model~C is checkpoint-contract mismatch evidence rather than a competing candidate. Together, these results support the thesis claim that production-style governance must verify the preprocessing contract end-to-end and must not infer deployment quality from internal diagnostic scores alone.

\textbf{Limitation.} The external evaluation is bounded to one external participant (User~7) and one unlabeled Garmin session. The reported numbers bound cross-user generalisation and runtime-monitoring behaviour for these specific datasets; they do not establish population-level generalisation, clinical validity, or production-grade deployment readiness.

\section{Chapter Synthesis}

\textbf{Strongly supported findings.} Five conclusions are strongly supported by the experiments. First, preprocessing consistency materially affects downstream behavior: gravity removal alone worsened collapse, while the gravity-plus-calibration combination broadened class use, and the final production contract is kept raw and explicitly governed to avoid unsupported scaler changes at inference. Second, governance policy design changes the operational safety profile of the pipeline: the \texttt{two\_of\_three} trigger rule sharply reduced false alarms without sacrificing episode recall on the tested replay. Third, calibrated MMD branch experiments show that stronger drift visibility can be achieved without changing the retained model, but that this visibility should be evaluated separately from mutation decisions. Fourth, collapse on a fixed production-style session can be driven primarily by model choice rather than by the input alone, as shown by the same-input old-versus-new comparison. Fifth, the ABC and external evaluation in Section~\ref{sec:abc_comparison} shows that the defended runtime candidate (Model~A) reports an honest external accuracy ceiling on User~7 (37.6\% accuracy, 34.1\% macro F1), that the strong all\_users score for Model~B does not transfer to User~7 once the non-persisted full-evaluation scaler and legacy native setup are taken into account, and that loading the same checkpoint without the matching preprocessing contract (Model~C) collapses accuracy to 7.6\% --- direct evidence that the model artifact and its preprocessing contract are inseparable governance objects.

\textbf{Partially supported findings.} The actual-versus-synthetic comparison suggests that uncertainty and temporal-instability signals can act as useful proxy monitors when labels are absent. Under degraded realism, confidence drops, uncertain-window rates rise, and temporal switching increases. MMD strengthens this proxy-monitoring evidence by surfacing 3 of 4 degraded/reference replay comparisons as warning-level drift cases while the current drift monitor surfaces none, but the staged-policy tests show that this does not by itself justify retraining. The Garmin unlabeled run (1{,}304 windows, mean confidence 0.393, drift \texttt{HEALTHY}, trigger \texttt{REVIEW}, \texttt{auto\_retrain=false}) extends this evidence to a real production-style session and demonstrates label-free runtime-style monitoring, but it remains a proof of concept on one session rather than evidence of broad runtime robustness. This supports the thesis monitoring story directionally; it does not establish universal calibration or out-of-distribution detection performance.

\textbf{What this chapter does not establish.} The evaluation does not prove subject-independent deployment quality, universal robustness across unseen domains, globally optimal retraining thresholds, or universal MMD cutoffs. The 37.6\% User~7 accuracy is not a deployment claim; it bounds the cross-user generalisation gap on a single external participant under the defended contract. The 90.8\% all\_users score for Model~B is not a deployment claim either; it is an internal diagnostic on data drawn from the same labeled population, run under a non-persisted full-evaluation scaler that does not transfer to external evaluation. The chapter also does not justify interpreting all routing changes as model-quality gains, as shown by the negative result, and it does not justify promoting MMD into the defended runtime mutation path. The supported thesis claim is narrower and more defensible: under the tested datasets, replay conditions, and one external participant, the pipeline is reproducible, operationally monitorable, and governable in a way that makes degradation and retraining decisions more explicit than a benchmark-only wearable HAR workflow.
