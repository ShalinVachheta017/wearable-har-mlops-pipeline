# 4.X Pretrained Runtime Model Artifact Analysis and Pipeline Diagnostic Findings

## 4.X.1 Received Artifact and Nominal Specification

The pretrained checkpoint `fine_tuned_model_1dcnnbilstm.keras` was provided as an external artifact prior to the pipeline integration phase and was the nominal baseline against which the retraining pipeline was to be compared. The checkpoint was reported to achieve approximately 87% macro-averaged F1 on the ICTH 2025 reference study and was cited as the fine-tuned variant of the 1D-CNN-BiLSTM model family introduced in that work. Programmatic inspection confirmed the expected architecture signature: an input tensor shape of (None, 200, 6), an eleven-class softmax output, a total parameter count of 499 131, and seventeen layers distributed across two convolutional blocks, two bidirectional LSTM blocks, a flattening stage, and a two-layer dense classifier. A companion metadata file `model_info.json` accompanied the checkpoint and was internally consistent with the inspected graph.

## 4.X.2 Diagnostic Methodology

To establish whether the observed accuracy gap on the local labeled dataset originated in preprocessing, in the weights themselves, or in the upstream data provenance, a systematic diagnostic procedure was designed covering more than twenty distinct preprocessing configurations. The configurations spanned five orthogonal axes: the choice of normalization variant (z-score, robust scaling, and no amplitude normalization), the sensor column order and the milliG-to-m/s² unit conversion factor, the optional application of Butterworth high-pass gravity removal and domain-mean calibration, per-user and per-session scalers fitted in isolation, and label mapping permutations consistent with alternative activity orderings reported in the reference literature. Model weight distributions were additionally examined layer by layer in order to distinguish a trained checkpoint from a partially initialised or truncated one, and the architectural identity of the pretrained and retrained variants was verified tensor by tensor.

## 4.X.3 Findings

Across the full configuration matrix, no preprocessing variant produced accuracy exceeding 18.5% on the labeled dataset, against the reported reference of 87.0%. The first-layer convolutional kernel exhibited a weight standard deviation of 0.239 and a broad tail distribution, and the batch-normalisation layers carried populated non-trivial running statistics, confirming that the checkpoint represented a genuinely trained network rather than a random or corrupted initialisation. A decisive observational signature was located in the final batch-normalisation layer preceding the classifier, whose running variance averaged 363.7 — a fingerprint of the activation scale encountered during the original training and inconsistent with the activations produced by the local dataset under any tested normalisation. Concurrently, the vertical accelerometer channel exhibited an empirical mean of −3.53 m/s² on the local dataset versus a value near −7.2 m/s² implied by the reference preprocessing, indicating a substantial difference in wrist-worn sensor orientation between the two studies. The git history of the artifact further supported an external provenance: the file was authored in May 2025, first committed to the repository in November 2025, and was never produced by any pipeline execution in this codebase. The retraining pipeline, when operating on the same labeled dataset and the same architecture definition, produced a validated model achieving 99.25% macro-F1 on the same evaluation set, thereby demonstrating that neither the preprocessing pipeline nor the network specification was the limiting factor.

## 4.X.4 Conclusion and Comparison Boundary

The convergent evidence supports the conclusion that the pretrained artifact was fine-tuned on a dataset distinct from the labeled dataset used in the present work, and that the local accuracy gap cannot be closed through inference-time preprocessing alone. In the absence of the original training corpus and the corresponding scaler statistics, the checkpoint does not admit a fair reproduced numerical comparison against models trained within this repository. The boundary is therefore narrow: the checkpoint remains the defended runtime model, while its published 87% figure is retained as an external reference rather than as a locally reproduced baseline. Retrained artifacts are treated as candidate models generated by the governance workflow and require labeled evaluation before any promotion decision.

## 4.X.5 Pipeline Design Decisions Motivated by this Finding

The diagnostic outcome directly shaped three design decisions in the final pipeline. First, trained artifacts are henceforth packaged jointly with their fitted scaler configuration and their user-split provenance, so that no future reader can load a checkpoint without the preprocessing context required to reproduce its reported numbers. Second, a batch-normalisation recalibration path (AdaBN) was retained in the retraining component in order to compensate for the class of distribution shift exemplified by the pretrained artifact, and its behaviour is traced through the standard monitoring component rather than being applied silently. Third, model provenance — including the git commit, the training-data hash, the scaler identity, and the evaluation protocol — is persisted as structured metadata alongside the model file, so that the condition diagnosed in this section cannot recur without being surfaced at load time.
