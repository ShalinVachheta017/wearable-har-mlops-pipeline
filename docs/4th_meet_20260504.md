## Main Investigation: 100% hand_tapping Collapse — Root Cause

### The dataset used (source of problem)

The pipeline auto-picks the **newest file by `st_mtime`**. The March 23 file
(`2025-03-23-15-23-10-accelerometer_data.csv`) was **last touched on May 3 at 18:45**
because the pipeline ran it earlier and modified the file's mtime. All July/August 2025
files have mtime from December 5 / January 14 and are therefore never picked.

This is a self-reinforcing loop. Once a file is processed, it becomes the "newest" and
gets processed every subsequent run.

### Production_X.npy — what the model actually received

Verified from `artifacts/20260503_184608/data_transformation/production_X.npy`:

| Channel | Mean | Std | Median |
|---|---|---|---|
| Ax | −0.159 m/s² | 0.109 | −0.162 |
| Ay | −0.185 m/s² | 0.274 | −0.189 |
| **Az** | **−9.823 m/s²** | **0.176** | **−9.826** |
| Gx | 0.492 deg/s | 5.32 | 0.499 |
| Gy | 0.151 deg/s | 4.72 | 0.145 |
| Gz | 0.132 deg/s | 1.86 | 0.147 |

**Az = −9.826 m/s² = exactly −1g.** The device was lying flat on a surface for the entire
60.5-minute session. Az std = 0.176 m/s² — almost no variation at all.
**This is not a worn-wrist recording. It is a desk artifact.**

G_mag_median = 0.5478 deg/s (essentially stationary). Every one of 1814 windows is the
same pattern: flat device, no rotation.

### The 8 contributing factors (verified with numbers)

**Factor 1 — Normalization OFF while model was trained normalized (PRIMARY)**

Scaler `scaler_train_only.json` confirms training used z-score:
- Az training mean = −3.5925 m/s², scale = 3.0806
- Gx training mean = 0.6734 deg/s, scale = 54.7905

`normalized_baseline.json` has mean = 0.000, std = 1.000 on all channels — built from
normalized training data. Config has `enable_normalization: false`. The model
receives raw m/s² inputs it has never seen.

**Factor 2 — Device flat on desk**

Az = −9.82 m/s² constant, Ax ≈ 0, Ay ≈ 0. Every window is identical. The model maps
this constant out-of-distribution pattern to hand_tapping with high confidence.

**Factor 3 — All 1814 windows are identical**

Because the device is flat and motionless, every window has the same feature values.
Whatever class the model maps the flat-device pattern to, it maps ALL windows there.

**Factor 4 — The 9.797σ drift is a measurement error, not real drift**

Computed manually from the archived npy:

| Channel | Production mean | Baseline mean | Drift |
|---|---|---|---|
| Ax | −0.159 | 0.000 | 0.159σ |
| Ay | −0.185 | 0.000 | 0.185σ |
| **Az** | **−9.823** | **0.000** | **9.797σ** ← all of it |
| Gx | 0.492 | 0.000 | 0.493σ |
| Gy | 0.151 | 0.000 | 0.151σ |
| Gz | 0.132 | 0.000 | 0.132σ |

The 9.797σ comes **entirely from the Az channel**. It is the raw gravity value
compared against a normalized baseline in the old debugging setup. The final
Stage 6 contract uses the raw physical baseline and skips mismatched
feature-space comparisons. Log also says `drifted channels: 1`,
confirming only one channel triggered.

Simulated with normalization ON: max drift drops to **1.262σ → HEALTHY** (below 1.8 threshold).
This old conclusion is superseded; do not enable normalization for final production inference.

**Factor 5 — Model has structural bias toward hand_tapping**

Mean probability per class across all 1814 windows:
- hand_tapping: **0.998035**
- ear_rubbing: 0.001818
- all others: < 0.0002

First 4 windows (session startup, device being placed) show hand_tapping 0.67–0.77 with
ear_rubbing as competitor (0.22–0.31). From window 4 onwards, device fully flat →
hand_tapping locks at 0.999+. Logit advantage of hand_tapping over best competitor:
mean = 6.94, max = 9.51.

**Factor 6 — Temperature calibration is hardcoded, not fitted**

`outputs/calibration/temperature.json` contains `{"temperature": 1.5, "fitted": false}`.
T=1.5 was set manually. Effect: confidence 0.998 → 0.989 (marginal).
To reduce 0.998 to 0.5 would require T ≈ 50. Calibration cannot fix the
overconfidence because it is not optimized on a validation set.

**Factor 7 — mtime feedback loop in file selection**

`src/components/data_ingestion.py:125` — `pairs.sort(key=lambda pair: max(pair[0].stat().st_mtime, ...)`.
March 23 mtime = May 3 18:45 (today's run touched it). All other files: December 5.
Same broken file will be picked on every future run unless `--accel-file` is passed.

**Factor 8 — Gyroscope sensor clipping distorts some windows**

Gx max = 800.86 deg/s, Gy max = 584.83 deg/s. Sensor FS range = 500 deg/s.
Clipped samples create flat plateaus in those channels. Appears in the first few
windows (startup motion), explaining why windows 0–3 have lower confidence
(0.67–0.95) vs windows 4+ (0.999+). Validation passes this as WARNING, not BLOCK.
